======================

💬 CHAT API CONSTRAINTS (FINAL)

These constraints define what the backend MUST and MUST NOT do.
They are intentionally strict to keep AI behavior clean, auditable, and stable.

1️⃣ /chat/session — Create Session
✅ MUST

Create a new session row

Generate a UUID session_id

Associate session with user_id

Mark session as active

Return only { session_id }

❌ MUST NOT

Store messages

Call AI

Generate summary

Infer any intent

2️⃣ /chat/message/user — Store User Message
✅ MUST

Store message with:

role = 'user'

session_id

content

Count ONLY user messages dynamically from DB

Decide summary trigger ONLY by count

should_update_summary = (user_message_count % 3 === 0)

✅ RESPONSE MUST BE
{
  "message": "User message stored",
  "message_count": <number>,
  "should_update_summary": <true|false>
}

❌ MUST NOT

Call AI

Analyze text

Detect emotion

Generate summary

Modify user text

📌 Backend is blind at this step

3️⃣ /ai/respond — AI Orchestration (INTERNAL)
✅ MUST

Fetch all messages for session

Fetch latest summary (or null)

Fetch last AI process state (or null)

Send raw data to Python AI

✅ PAYLOAD SENT TO AI
{
  "session_id": "<uuid>",
  "messages": [...],
  "summary": "<string|null>",
  "last_process_state": {...|null}
}

❌ MUST NOT

Change message text

Filter messages

Decide therapy logic

Modify AI output

📌 Backend is a pipe, not a brain

4️⃣ AI → Backend Response (AUTHORITATIVE)
✅ AI RESPONSE IS FINAL

Backend must accept as truth:

{
  "message": "<ai_text>",
  "debug": {...},
  "clinical": {...},
  "process_state": {...}
}

❌ Backend MUST NOT

Reinterpret

Sanitize

Rephrase

Remove debug/clinical data internally

5️⃣ /chat/message/ai — Store AI Response
✅ MUST STORE (AS-IS)

AI message → message table (role = 'ai')

Debug state → debug table

Clinical state → clinical table

Process state → process table

❌ MUST NOT

Modify AI text

Decide phase

Merge logic

Infer meaning

📌 AI owns intelligence — backend owns storage

6️⃣ SUMMARY RULE (GLOBAL)
📏 Trigger Rule
IF (user_message_count % 3 === 0)
→ trigger AI summary

❌ STRICT

No time-based summaries

No emotion-based summaries

No backend decision-making

7️⃣ /ai/summarize — Internal Only
✅ MUST SEND

Recent messages

Previous summary (or null)

❌ MUST NOT

Send full history

Modify summary text

Store summary directly

8️⃣ /chat/summary — Store Summary
✅ MUST

Store summary exactly as received

Overwrite logically (latest = authoritative)

❌ MUST NOT

Edit text

Generate summary

Merge summaries

9️⃣ /chat/context/:session_id — Fetch Context (CRITICAL)
✅ MUST RETURN
{
  "session": {...},
  "summary": {...|null},
  "process_state": {...|null},
  "clinical_signals": {...|null},
  "messages": [...]
}

✅ ORDER

Messages must be chronological

Summary must be latest only

❌ MUST NOT

Recompute state

Generate AI

Modify content

📌 This endpoint is used for:

Session resume

AI prompt building

Debugging

Auditing
